# ОБЩАЯ ТЕОРИЯ #

*Сетевой протокол* - это набор правил, определяющий принципы
взаимодействия устройств в сети. Чтобы отправка и получение информации
прошли успешно, все устройства-участники процесса должны принимать
условия протокола и следовать им. В сети их поддержка встраивается или в
аппаратную часть (в «железо»), или в программную часть (в код системы),
или и туда, и туда.

Для взаимодействия протоколов между собой существуют разные модели,
основные из которых OSI и TCP/IP.
________________________________________________________________________

Термины:

- *Инкапсуляция* - процесс перехода данных в биты.
- *Декапсуляция* - процесс, обратный инкапсуляции.
- *ADU* (Application Data Unit) - пакет данных целиком.
- *PDU* (Protocol Data Unit) - основная часть пакета, передаваемого по
    к-л протоколу.
________________________________________________________________________

### МОДЕЛЬ OSI ###

*OSI* (Open Systems Interconnection) основана на принципе разделения
коммуникационной системы на семь отдельных уровней. Cамым верхним
является седьмой (прикладной), а самым нижним - первый (физический).
________________________________________________________________________

Все семь уровней модели OSI можно условно разделить на две группы:

- Media Layers (уровни среды).
- Host Layers (уровни хоста).

Уровни группы Media Layers (1-3) занимаются передачей информации (по
кабелю или беспроводной сети) и исп-ся сетевыми уст-вами. Уровни группы
Host Layers (4-7) исп-ся непосредственно на уст-вах, т.е. компьютерах
или мобильные устройствах.

Уровни:

1. *Физический* - отвечает за обмен физическими сигналами м/ физическими
    устройствами («железом») в виде бит. За этот уровень отвечают кабеля
    или беспроводные способы связи наподобие Wi-Fi, 4G, Bluetooth и т.д.

2. *Канальный* - для адресации в сетях. Канальный уровень получает биты
    и превращает их в кадры (frame, также «фреймы»). Задача здесь -
    сформировать кадры с адресом отправителя и получателя, после чего
    отправить их по сети. У канального уровня есть два подуровня - это
    MAC и LLC.
    
    - MAC (Media Access Control, контроль доступа к среде) - отвечает за
        присвоение физических MAC-адресов.
    - LLC (Logical Link Control, контроль логической связи) - занимается
        проверкой и исправлением данных, управляет их передачей. Хотя,
        если быть точными, LLC нельзя отнести полностью ни к первому,
        ни ко второму уровню - он между.
    
    Основной протокол - ARP (Address Resolution Protocol - протокол
    определения адреса). С помощью него 64-битные MAC-адреса
    сопоставляются с 32-битными IP-адресами и наоборот.

3. *Сетевой* - для маршрутизации, т.е. построения маршрута от одного
    устройства к другому с использованием MAC-адресов и учетом всех
    потенциальных неполадок в сети. Для обеспечения этого уровня
    существуют уст-ва - маршрутизаторы.

4. *Транспортный* - уровень, отвечающий за транспортировку пакетов.
    По сути является посредником м/ Media Layers и Host Layers. К этому
    уровню относятся протоколы TCP и UDP.

5. *Сеансовый* - первый уровень, который оперирует уже чистыми данными,
    а не набором битов. Отвечает за поддержку сеанса или сессии связи,
    управляет взаимодействием между приложениями, открывает возможности
    синхронизации задач, завершения сеанса, обмена информации.

6. *Представления данных* - отвечает за преобразование протоколов и
    кодирование/декодирование данных.

7. *Прикладной* (приложений) - то, с чем взаимодействуют пользователи.
    Все услуги, получаемые седьмым уровнем от других, используются для
    доставки данных до пользователя. Протоколам седьмого уровня не
    требуется обеспечивать маршрутизацию или гарантировать доставку
    данных, когда об этом уже позаботились предыдущие шесть. Задача
    седьмого уровня - исп-ть свои протоколы, чтобы пользователь увидел
    данные в понятном ему виде.
________________________________________________________________________

OSI имеет ряд недостатков как модель:

- Несоответствие реальности - это можно заметить по вещам, находящимся
    м/ уровнями, и расплывчатым понятиям.
- Плохая технология - часто дублируют другу друга, ф-ции распределены по
    уровням неравнозначно, а одни и те же задачи могут быть решены на
    разных уровнях.
- Кроме того, долгая разработка модели и плохое взаимодействие с
    общественностью сыграло огромную роль в популярности модели, и пока
    она разрабатывалась, на рынке установил свое превосходство TCP/IP.

Из-за этого при работе вне сетевых технологий OSI скорее является
громоздкой моделью, где-то - идеалистической, а где-то - необоснованно
запутанной. Поэтому обычно люди пользуются моделью TCP/IP. Но при работе
с сетевой коммутацией и иногда - с другими сетевыми технологиями исп-ся
модель OSI.
________________________________________________________________________

### МОДЕЛЬ TCP/IP ###

*Стек протоколов TCP/IP* - модель взаимодействия протоколов связи,
широко используемая и лежащая в основе сети Интернет. В отличие от OSI,
содержит в себе четыре уровня.
________________________________________________________________________

Уровни:

1. *Канальный* - определяет то, как происходит обмен информацией на
    уровне сетевых уст-в, определить, как информация будет передаваться
    от одного уст-ва к другому. Информация здесь кодируется, делится на
    пакеты и отправляется по нужному каналу, т.е. среде передачи.
    Основным протоколом (или скорее стандартом организации) является
    Ethernet.

2. *Межсетевой* - для обеспечения взаимодействия сетей между собой.
    Локальные сети по всему миру объединены в глобальную, а передачу
    данных между этими сетями осуществляют магистральные и пограничные
    маршрутизаторы. Основной протокол - IP.

3. *Транспортный* - служит для обеспечения доставки информации. Основные
    протоколы - TCP и UDP.

4. *Прикладной* - для взаимодействия между пользователем и остальными
    уровнями, представления данных в понятном и возможном к исп-ю и
    интерпретации виде. Здесь есть мн-во протоколов наподобие HTTP, FTP,
    SMTP и т.д.
________________________________________________________________________

# ПРОТОКОЛЫ СВЯЗИ #

Протоколы сети:

- Канальный уровень:

    - Ethernet - стандарт организации локальных сетей (LAN - Local Area
        Network, WAN - Wide Area Network) с помощью проводных - и только
        проводных - соединений.

- Транспортный уровень:

    - TCP - Transmission Control Protocol - протокол контроля передачи.
        Разбивает данные на блоки, а при приеме - собирает блоки
        обратно. Протокол отличается надежностью и требуется для точной
        передачи данных. Устанавливает соединение и следит, чтобы все
        дошло в том формате, в котором должно быть, устраняя ошибки по
        ответу от принимающей стороны. Поэтому относительно медленный.

    - UDP - User Datagram Protocol - протокол пользовательских
        датаграмм. Не отправляет ответ о полученных данных, из-за чего
        менее надежен, но более быстр. Каждый блок данных в этом
        протоколе представляет собой самостоятельную единицу.

    - SCTP - Stream Control Transmission Protocol - протокол передачи
        управления потоком. Поддерживает многоадресное соединение,
        позволяя быстро переключаться между путями.

    - RTP - Real-time Transfer Protocol - транспортный протокол
        реального времени. Применяется вместе с RCTP для контроля,
        исп-ся в IP-телефонии.

- Межсетевой уровень:

    - IP - Internet Protocol - протокол Интернета. Предназначен для
        маршрутизации запросов.

    - ICMP - Internet Control Message Protocol - для передачи сообщений
        об ошибках и диагностической информации при передаче данных меж
        устройствами.

    - OSPF - Open Shortest Path First - протокол поиска наилучшего
        свободного пути от исходного до конечного маршрутизатора.

- Прикладной уровень:

    - FTP - File  Transfer Protocol - протокол передачи файлов.
        Клиент-серверный протокол связи с 2 линиями - командной и
        транспортной.

    - DNS - Domain Name System - словарь доменов. Связывает вписанный
        адрес сайта в строку браузера и его IP-адрес.

    - HTTP(S) - HyperText Transfer Protocol (Secured) - протокол
        передачи гипертекста. Используется для передачи веб-страниц с
        использованием гиперссылок. Связь вида запрос-ответ. Есть
        команды GET, POST, PUT, DELETE. В современности данные запросы
        передают не только гипертекст, но и различные данные.

    - SSH - Secure Shell - защищенный протокол, который исп-ся для
        подключения к серверам. Клиент-сервер.

- Кроме того:

    - Torrent - пиринговый протокол связи. Пиринговый =
        децентрализованный, где все участники равны между собой. В
        случае данного протокола файл передается от всех участников
        соединения по частям, в том числе от тех, кто в данный момент
        данный файл скачивает.
    
    - Modbus - самый распространенный промышленный протокол для
        M2M-взаимодействия. Подвиды:
        
        - Modbus RTU - данные кодируются в двоичный формат, и
            разделителем пакетов служит временной интервал. Этот
            протокол критичен к задержкам и не может работать, например,
            на модемных линиях. По интерфейсу RS-232.
        - Modbus TCP - структура пакетов схожа с Modbus RTU, данные
            также кодируются в двоичный формат, и упаковываются в
            обычный TCP-пакет, для передачи по IP-сетям. Проверка
            целостности, используемая в Modbus RTU, не применяется, так
            как TCP уже имеет собственный механизм контроля целостности.
            Порт: 502.
        
        Slave - получатель, master - отправитель. Только отправитель
        может инициализировать отправку и только он знает о состоянии
        подключения. Слейвов мб не более 247, адрес 0 используется для
        широковещательных запросов от мастера, у мастера адреса нет.

# СТАНДАРТЫ И СЕТИ #

- VPN - Virtual Private Network - виртуальная приватная сеть.
    Защищенный тип соединения для удаленного доступа к приватным
    данным или для создания тоннеля между серверами с приватными
    данными. Работает так:

    - Пользователь выбирает сервер в сервисе VPN и подключается к
        нему со своего устройства.
    - VPN-сервис создает зашифрованный туннель между клиентом и
        сервером. В нем шифрует передаваемые данные с помощью
        протокола.
    - VPN-сервер получает и расшифровывает трафик. Для этого он
        использует специальные ключи шифрования.
    - VPN-сервер заменяет информацию о пользователе на свою и
        перенаправляет на целевой сайт клиентский запрос, с которым
        нужно установить соединение.
    - VPN-сервер получает ответ, шифрует и перенаправляет его
        пользователю. Для расшифровки данных VPN-клиент и сервер
        используют специальные ключи шифрования.

    Имеет ряд различных протоколов. Подробнее см. следующую ссылку.
