# КРАТКАЯ ТЕОРИЯ #

Определения:

- *СУБД* - система управления БД: MySQL, SQLite, PosgreSQL и др.
- *Реляционные БД* - базы данных с таблицами с возм-тью связываться м/
    собой (от relation - связь).
- *SQL* - structured query language - язык запросов, который применяют
    для работы с базами данных, структурированными особым образом.
    Плюсы SQL: удобный формат данных, универсальный для всех языков, с
    набором удобного функционала для преобразования таблиц и их эл-тов.
- *API* - application programming interface - программный интерфейс,
    предназначенный в контексте данного конспекта для взаимодействия с
    СУБД.
________________________________________________________________________

Принято по оформлению:

- Команды, функции, типы данных - заглавные буквы.
- Названия, поля - маленькие буквы.

Тем не менее, это лишь рекомендации, притом куда более необязательные,
чем в оформлении кода на языках программирования. Поэтому в разных
источниках будут встречаться разные записи, т.к. SQL нечувствителен к
регистру.

Если название чего-либо совпадает с оператором, то следует его заключить
в апострофы. Например, есть оператор FROM, и если при этом имеется поле
from, то поле следует записывать при вызове команды как 'from'.
________________________________________________________________________

Важные особенности:

- Имеет скрытое поле rowid, который представляет собой уникальный id
    строки, от 1 и далее. В том числе по нему можно связывать таблицы.

# PYTHON #

`psycopg2` - модуль для работы с PostgreSQL.

`conn = psycopg2.connect(dbname='database', user='db_user', password='mypassword', host='localhost')`
\- подключиться к БД. Здесь password указывается из установленного в БД,
host может принимать значение 'localhost' - локальная БД, или
IPv4-адреса, и тогда также нужно использовать пар-р port типа данных
str.

`cursor = conn.cursor()` - получить курсор. Через курсор происходит
дальнейшее общение с БД. Имеет пар-р cursor_factory - для задания типа
возвращаемых данных при fetch-методах. Например, по умолчанию возвращает
данные в виде кортежей, а значение `psycopg2.extras.DictCursor` позволит
исп-ть вместо кортежей словари с ключами - именами полей.

`conn.close()` - закрывает связь с БД.
________________________________________________________________________

Можно через контекстный менеджер:

```python
with psycopg2.connect(...) as conn:
    with conn.cursor() as cursor:
        ...
```
________________________________________________________________________

`cursor.execute("""<sql_code>""")` - выполить sql_code.

`res = cursor.fetchall()` - получить результат последнего запроса.\
`.fetchone()` - возвращает первую запись из последнего запроса.\
`.fetchmany(size)` - возвращает не более size записей из последнего
запроса.

Тип возвращаемых данных - список кортежей.
________________________________________________________________________

Для забора данных часто удобнее использовать конструкцию:

```python
for res in cursor:
    ...
```

Получится по одной записи выполнять тело цикла for. Это чтоб не занимать
память мн-вом записей одновременно.
________________________________________________________________________

`conn.execute('SELECT <smth> FROM <smwr> WHERE col1 = %s', (some_var,))`
\- пример динамически формируемого запроса с помощью классического
форматирования строк. Таким образом формируется запрос, куда можно
подставлять данные из переменных.

`cursor.execute('SELECT <smth> FROM <smwr> WHERE col1 = %(key)s', {'key': 'value'})`
\- с именованными аргументами, соответственно, также работает.
________________________________________________________________________

# ЗАПРОСЫ POSTGRESQL #

### ТИПЫ ДАННЫХ ###

Типы данных: см. документацию PostgreSQL глава 8.

*Основные числовые*:

- `smallint`, `int2` - целочисленный, 2 байта.
- `integer`, `int`, `int4` - целочисленный, 4 байта.
- `bigint`, `int8` - целочисленный, 8 байт.
- `numeric(precision, scale)`, `decimal(precision, scale)` - для дробных
    или целых с большим кол-вом цифр. scale - число знаков после
    запятой, precision - общее число цифр. Например, `numeric(6,2)` -
    для чисел типа `abcd.ef`.
- `real`, `float4` - дробный, 4 байта, точность 6 знаков. От 1E−37 до
    1E+37. Доступны значения NaN, Infinity и -Infinity.
- `double precision`, `float8` - дробный, 8 байт, точность 15 знаков. От
    1E−307 до 1E+308. Доступны значения NaN, Infinity и -Infinity.
- `float(p)` - обобщенный вид двух предыдущих. По умолчанию float8, но
    при значениях p от 1 до 24 эквивалентно float4.
- `serial`, `smallserial`, `bigserial` - последовательные, см. дальше.

*Основные символьные*:

- `text` - безлимитная длина. Обычно исп-ся именно этот тип данных, если
    не нужны ограничения длины.
- `character varying(n)`, `varchar(n)` - символьный тип с изменяемым
    размером и с пределом в n.
- `character(n)`, `char(n)`, `bpchar(n)` - символьный тип с
    фиксированным размером в n. При присваивании менее длинной строки
    дополняет пробелами.
- `bpchar` - безлимитная длина.

*Основные прочие*:

- `boolean`, `bool` - логический.
- `bytea` - строка байтов, 1 или 4 байта + сама байтовая строка.
- `time`, `date`, `timestamp`, `interval` - типы данных даты-времени.
    Про них подробнее в соответствующем разделе данного конспекта или в
    Моргунове.
- `json`, `jsonb` - для JSON.
________________________________________________________________________

`CREATE TYPE mood AS ENUM ('sad', 'ok', 'happy');` - задать свой тип
данных.

`<some_value>::<type>` - для преобразования some_value в тип данных
type. Чаще всего используется для получения результатов агрегирующей
ф-ции в обрабатываемый тип данных или для получения значений к-л типа
данных из строки - `'<some_string>'::<type>`.
________________________________________________________________________

`имя-атрибута тип-данных[]` - задать массив переменной длины.

`'{ 1, 3, 5, 6, 7 }'::integer[]` - пример преобразования строки в массив
целых чисел. Можно определенные массивы задавать не только так, но и
через `ARRAY[ <val1>, <val2>, ... ]`.

Через UPDATE SET можно сделать:

- `<arr> = <arr> || <val/other_arr>` - конкатенация.
- `<arr> = array_append( <arr>, <val> )` - добавить val в конец arr.
- `<arr> = array_prepend( <val>, <arr> )` - добавить val в начало arr.
- `<arr> = array_remove( <arr>, <val> )` - убрать val из arr.
- `<arr>[ <ind> ] = <val>` - замена значения arr по индексу ind на val.
- `<arr>[ <ind1>:<ind2> ] = ARRAY[ <val1>, <val2>, ... ]` - замена через
    срез.

Также доступны ф-ции:

- `array_position( <arr>, <val> )` - поиск первого вхождения val в arr,
    если не находит - Null.
- `<arr1> @> <arr2>` - проверка, что в левом массиве содержатся все
    эл-ты правого. Так можно проверять наличие целого набора значений в
    к-л массиве.
- `<arr1> && <arr2>` - проверка наличия непустого мн-ва пересечения arr1
    и arr2.
- `SELECT unnest( <arr_column> ) AS <alias>` - развернуть массив в
    столбец.
________________________________________________________________________

`CREATE TABLE имя-таблицы ( имя-столбца serial );` - задание таблицы с
полем типа данных serial. Это удобно, т.к. эквивалентно записи в других
типах данных:

```sql
CREATE SEQUENCE имя-таблицы_имя-столбца_seq;
CREATE TABLE имя-таблицы
(
имя-столбца integer NOT NULL
DEFAULT nextval( 'имя-таблицы_имя-столбца_seq' )
);
ALTER SEQUENCE имя-таблицы_имя-столбца_seq
OWNED BY имя-таблицы.имя-столбца;
```

По сути говоря, позволяет создавать последовательные уникальные
положительные значения int.

`smallserial` и `bigserial` для serial аналогичны smallint и bigint для
int.
________________________________________________________________________

Для задания строк используются одинарные кавычки или удвоенные $:
`$$ABC$$` или `'ABC'`

В строках для экранирования некоторых символов исп-ся их удваивание.
Например, для записи `"a'b\c"` надо исп-ть `'a''b\\c'`. Но при задании
строки в \$$ не требуется экранирование: `'a''b\\c'` эквивалентно
`$$a'b\c$$`.

Требующие экранирования символы: `'\`.

Для использования строковых констант в стиле языка С нужно исп-ть
`E'<some_string>'`. Например, так можно исп-ть знаки \n, \t и т.д. Тогда
для экранирования как обычно исп-ся обратный слеш `\<char>`.
________________________________________________________________________

### СОЗДАНИЕ И УДАЛЕНИЕ ###

Создание таблицы:

```sql
CREATE TABLE [IF NOT EXISTS] имя-таблицы
(
    имя-поля тип-данных [ограничения-целостности],
    имя-поля тип-данных [ограничения-целостности],
    ...
    имя-поля тип-данных [ограничения-целостности],
    [ограничение-целостности],
    [первичный-ключ],
    [внешний-ключ]
);
```

Пример:

```sql
CREATE TABLE aircrafts
(
    aircraft_code char( 3 ) NOT NULL,
    model text NOT NULL,
    range integer NOT NULL,
    CHECK ( range > 0 ),
    PRIMARY KEY ( aircraft_code )
);
```

Про ограничители и ключи далее.
________________________________________________________________________

Ограничители:

- `NOT NULL` - не Null, т.е. требование чем-то заполнить (пустая строка,
    нулевое значение и т.п., но не Null).
- `DEFAULT smth` - установить значение по умолчанию smth.
- `UNIQUE` - требование уникальности значений данного поля.
- `CHECK (cond)` - проверка условия.

Команда `CHECK (cond)` позволяет проверять, подходят ли значения по
к-л условию, задавая т.о. ограничения для значений атрибута. Может
относиться как к атрибуту, так и к таблице в целом, соответственно и
объявляется.

Таким проверкам и ограничителям можно давать имена, чтобы при их
нарушении в сообщении об ошибке было использовано данное имя
ограничителя для большей ясности проблемы. Для этого при объявлении
атрибута (на примере CHECK):

```sql
имя-атрибута-1 тип-данных,
    CONSTRAINT имя-проверки CHECK условие-атрибута-1,
```

Можно также для `UNIQUE (имя-атрибута, имя-атрибута, ...)`.
________________________________________________________________________

Ключи:

- *Первичный ключ*:

    `PRIMARY KEY (имя-атрибута, имя-атрибута, ...)` - обозначение за
    первичный ключ, который должен быть уникальным. Самостоятельно
    накладывает ограничители UNIQUE и NOT NULL. Предназначен для
    уникальной идентификации записи в таблице и исп-ся для связи с
    другими таблицами в БД.

    `имя-поля тип-данных PRIMARY KEY`, `PRIMARY KEY (имя-атрибута)` -
    способы задать первичный ключ: при объявлении поля или отдельно в
    конце объявления полей таблицы соответственно.

    Для составного ключа задается всегда отдельно с перечислением
    атрибутов, в него входящих.

- *Внешний ключ*:

    Внешний ключ отвечает за связь с полями другой таблицы в данной БД и
    объявление поля внешним ключом эквивалентно по своей сути объявлению
    ссылки на поле из другой таблицы. Такая практика также не даст
    добавлять в ссылающуюся таблицу строки в поле внешнего ключа со
    значением, которого нет в соответствующем поле в ссылочной. Нужны
    для поддержания ссылочной целостности.

    Задается следующим образом:

    ```sql
    FOREIGN KEY (имя-атрибута)
        REFERENCES таблица ( имя-атрибута )
        ON DELETE указание
        ON UPDATE указание
    ```

    Или при задании поля (с возм-тью добавить указания ON DELETE и ON
    UPDATE):

    `имя-атрибута тип-данных REFERENCES таблица(имя-атрибута)`

    `ON DELETE` дает указания, что делать в ссылающейся таблице с
    записями в случае удаления ключа в ссылочной таблице.

    - `ON DELETE CASCADE` - связывает удаление конкретного ключевого
        значения из внешней таблицы с удалением всех записей в данной с
        удаляемым значением ключа (по каскаду).
    - `ON DELETE RESTRICT` или `ON DELETE NO ACTION` (по умолчанию) -
        если в таблице есть строки, ссылающиеся на удаляемую строку в
        ссылочной таблице, то операция удаления будет отменена и будет
        выведено сообщение об ошибке.
    - `ON DELETE SET NULL` - установить NULL. Из очевидного, для работы
        данного указания нужно, чтобы на атрибутах не было ограничения
        NOT NULL.
    - `ON DELETE SET DEFAULT` - установить DEFAULT, если есть.

    На `UPDATE` - обновлении поля в ссылочной таблице - те же указания
    аналогично.
________________________________________________________________________

Удаление таблицы name:

- `DROP TABLE name;` - удалить. Если не существует, выдаст ошибку.
- `DROP TABLE IF EXISTS name;` - удалить, если существует. Не выдаст
    ошибку, если не существует.
- `DROP TABLE name CASCADE;` - для ссылочных таблиц, чтобы удалить
    связи.

### РЕДАКТИРОВАНИЕ ###

Вставка записей (можно несколько сразу):

```sql
INSERT INTO имя-таблицы [( имя-атрибута, имя-атрибута, ... )]
    VALUES ( значение-атрибута, значение-атрибута, ... ),
           (...);
```

Пример:

```sql
INSERT INTO aircrafts ( aircraft_code, model, range )
    VALUES ( '773', 'Boeing 777-300', 11100 ),
           ( '763', 'Boeing 767-300', 7900 ),
           ( '733', 'Boeing 737-300', 4200 );
```
________________________________________________________________________

Обновление данных в таблице:

```sql
UPDATE имя-таблицы
    SET имя-атрибута1 = значение-атрибута1,
        имя-атрибута2 = значение-атрибута2, ...
    WHERE условие;
```

Условие нужно для выбора записей, которые нужно обновить. При неуказании
условия, соответственно, обновятся все записи.
________________________________________________________________________

`DELETE FROM имя-таблицы WHERE условие;` - удаление записей из таблицы.
Условие - аналогично условию в UPDATE.
________________________________________________________________________

`COMMENT ON COLUMN table.col IS 'comment';` - установить комментарий к
полю таблицы.
________________________________________________________________________

### ВЫБОРКА ###

Шаблон выборки:

```sql
SELECT attr_name, attr_name, ...
    FROM table_name
    JOIN table_name ON join_cond
    WHERE cond
    GROUP BY attr_name
    HAVING having_cond
    UNION/INTERSECT/EXCEPT table_uie
    ORDER BY attr_name
    LIMIT max OFFSET n
```
________________________________________________________________________

Выборка:

```sql
SELECT имя-атрибута, имя-атрибута, ...
    FROM имя-таблицы
    WHERE условие;
```

Можно использовать `*` вместо имен атрибутов для забора всего.

`SELECT DISTINCT col FROM table_name` - получить выборку уникальных
вхождений по полю col.

`SELECT col AS new_name FROM table AS new_table_name;` - использовать
элиас для имени атрибута или таблицы с помощью AS. Часто пригождается
при агрегировании или расчете ф-ций. Для элиасов таблиц есть другой
способ использования, см. JOIN.
________________________________________________________________________

Условие может принимать форму `colX знак_сравнения num` (сравнение).

Знаки сравнения, операторы и предикаты:

- `=`, `==` - равно для чисел и строк.

- `<`, `<=`, `>`, `>=`, `!=` - понятно.

- `<>` - не равно.

- `BETWEEN x AND y` - предиката значения между x и y.

- `EXISTS` или `NOT EXISTS` - предиката существования, наличия.

- `LIKE` - равно для строк + оператор шаблонов. Например,
    `str1 LIKE 'abc'`. Также есть спецсимволы:
    - `%` - любое продолжение строки.
    - `_` - один любой символ.
    > **НО!** очень ресурсоемкая операция.

- `NOT LIKE` - отрицание LIKE.

- `~` - поиск по шаблону с учетом регистра. Есть отрицание: `!~`.
    Поддерживает регулярные выражения POSIX:
    `SELECT smth FROM table WHERE col ~ '<posix_expression>';`.

    Здесь POSIX-выражение вида:
    `^(smth|smth|...)` или `\(...)` или `(...)$`
    - `^` или `\` или `$` - искать шаблон в начале, или в составе, или в
        конце.
    - smth - шаблон для поиска.
    - `|` - оператор ИЛИ.

    Экранирование спецсимволов через `\`.

`cond1 OPERATOR12 cond2 OPERATOR23 cond3 ...` - составные условия, где
OPERATORXY - логический оператор.

Логические операторы:

- `AND`, `OR`, `NOT`.
    > **ВАЖНО!** У NOT приоритет выше, чем у AND, а у AND выше, чем
        у OR.
- `IN` - предиката вхождения в мн-во значений (например,
    `col IN(a, b, c...)`).
________________________________________________________________________

**Вычисляемые столбцы**:

Можно выписывать арифметические выражения с полями в SELECT в качестве
столбцов. Пример:

`SELECT model, range, range / 1.609 AS miles FROM aircrafts;`

Здесь существуют ф-ции:

- `round(smth, digits)` - округлить smth до digits знаков после точки.
- `array_length(arr, dim_n)` - длина измерения номер dim_n массива arr.
    Если вместо arr что-то одномерное, например, какое-то поле, то
    `dim_n = 1`. И т.д.
- `length(col_name)` - длина строкового типа данных.

Можно использовать и другие конструкции, например:

```sql
CASE WHEN условие THEN выражение
    [ WHEN ... ]
    [ ELSE выражение ]
END
```

Такая конструкция при условиях выдает соответствующие значения, собирая
новый столбец.
________________________________________________________________________

У SELECT также есть оператор `ORDER BY colX KWORD`, позволяющий
отсортировать выдаваемый результат по какому-либо порядку поля colX,
определяемому KWORD. По умолчанию стоит по возрастанию (`ASC`). По
убыванию: `DESC`.
________________________________________________________________________

**Группировка записей**:

Группировка позволяет произвести агрегирование по группам. Проще всего
объяснить на примере. Следующий запрос считает сумму очков для каждого
уникального user_id, возвращая таблицу 2xN, где N - число пользователей,
набравших больше 10 очков:

```sql
SELECT user_id, sum(scores) AS sum
    FROM table_name
    GROUP BY user_id
    HAVING sum > 10;
```

Агрегирующие функции:

Предназначены для агрегирования значений по какому-то принципу. Имеют
наименьший приоритет. GROUP BY в основном исп-ся вместе с ними.

Список агрегирующих функций:

- `COUNT(*)` - возвращает кол-во строк в таблице или результате запроса.
- `COUNT(expression)` - возвращает кол-во не NULL значений в указанном
    столбце.
- `SUM(expression)` - возвращает сумму значений в столбце.
- `AVG(expression)` - возвращает среднее значение в столбце.
- `MIN(expression)` - возвращает мин. значение в столбце.
- `MAX(expression)` - возвращает макс. значение в столбце.
- `ARRAY_AGG(expression)` - возвращает массив значений из столбца.
- `STRING_AGG(expression, delimiter)` - объединяет строковые значения из
    столбца в одну строку, используя указанный разделитель.
- `BIT_AND(expression)` - выполняет побитовое AND для числовых значений.
- `BIT_OR(expression)` - выполняет побитовое OR для числовых значений.
- `BOOL_AND(expression)` - логическое И для столбца: возвращает TRUE,
    если все значения в столбце TRUE, иначе FALSE.
- `BOOL_OR(expression)` - логическое ИЛИ для столбца: возвращает TRUE,
    если хотя бы одно значение в столбце TRUE, иначе FALSE.

`HAVING cond` - позволяет вытащить данные, выполняющие условия, после
группировки. Например, `HAVING col >= n`.
________________________________________________________________________

Также можно ограничить число выводящихся строк путем оператора
`LIMIT max`. Если хочется пропустить первые n строк получаемой
выборки, то надо дописать `LIMIT max OFFSET n`.
________________________________________________________________________

`JOIN`, `UNION` и проч. неописанные - см. ниже в отдельных подглавах.

### СВЯЗЫВАНИЕ ТАБЛИЦ (JOIN) ###

Связывание двух таблиц по к-л пар-ру производится с помощью след.
команды:

`JOIN table_name ON join_cond`

Общий синтаксис `SELECT` в таком случае выглядит так:

Получаем выборку из таблиц tablex и tabley, где главной таблицей
обозначим tablex. Обращение к полям происходит через `table_name.col`,
но при уникальности названия среди всех таблиц можно таблицу не
указывать. Оператор `JOIN` позволяет связать две таблицы для
соответствия пар-ров в выборке между таблицами. В данном случае к
главной таблице tablex подвязывается таблица tabley по критерию, что
colx из tablex является тем же или принимает те же значения, что и coly
из tabley.

```sql
SELECT tablex.col1, tabley.col2, ... FROM tablex
    JOIN tabley ON tablex.colx = tabley.coly;
```

JOIN как бы относится к оператору FROM, подсказывая ему сразу несколько
таблиц на условии связывания.

Простой пример: две таблицы users (поля: name, sex, old, score) и games
(поля: user_id, score, time). Для них след. запрос выведет таблицу с
именами, полом и счетом за игру. При этом вывод подобен выводу данных по
счету из games, но с подтягиванием имен и полов вместо id пользователя.

```sql
SELECT name, sex, games.score FROM games
    JOIN users ON games.user_id = users.rowid;
```
________________________________________________________________________

У JOIN есть несколько типов:

- `JOIN`, он же `INNER JOIN` - см. выше. Для каждой записи в первой
    таблице присоединяется запись из второй, если имеется. Т.о. в
    итоговом результате будут только те записи из первой таблицы с
    присоединенным к ним записями из второй, которым есть соответствие,
    и наоборот. В примере выше, если в games есть некая игра с user_id,
    которому нет соответствия в users, то эта строчка не выведется.
- `LEFT JOIN`, `LEFT OUTER JOIN` - сначала INNER JOIN, а затем добавляет
    оставшиеся без соответствия записи из первой таблицы, ставя в
    соответствие значения NULL. Т.о. этот запрос позволяет вывести
    запись, даже если во второй таблице соответствия нет.
- `RIGHT OUTER JOIN` - обратная LEFT JOIN, т.е. INNER JOIN + записи из
    второй таблицы без соответствия в первой, NULL в соответствующие
    значения.
- `FULL OUTER JOIN` - INNER JOIN + записи как в LEFT JOIN + записи как в
    RIGHT JOIN, т.е. комбо двух выше.
- `CROSS JOIN` - декартово перемножение, или все возможные сочетания
    записей из первой и второй таблицы.
________________________________________________________________________

Вместо полных имен таблиц можно исп-ть элиасы. В запросе ниже для
таблицы tablex задан элиас x, а для tabley - y.

```sql
SELECT y.col1, x.col1 FROM tablex x
    JOIN tabley y ON x.id = y.x_id;
```
________________________________________________________________________

JOIN можно внутри SELECT исп-ть несколько раз, для каждой связываемой
таблицы свой JOIN.

Кроме того, такое можно проворачивать с одной и той же таблицей, задавая
разные элиасы. Иногда это может пригодиться.
________________________________________________________________________

Есть альтернативная запись для JOIN через WHERE:

```sql
SELECT x.colx1, x.colx2, ..., y.coly1, ...
    FROM tablex x, tabley y
    WHERE join_cond
        AND cond;
```

Также при одинаковых именах полей, по которым связываются таблицы, можно
использовать следующую запись:

```sql
SELECT x.col1, y.col2, ...
    FROM tablex x
    JOIN tabley y USING (col);
```

Есть также возм-ть задать ключ присоединения неявно, где PostgreSQL сам
определяет, какие поля являются ключом присоединения (на самом деле как
USING, одинаковые имена полей, а в случае, если не находит таковых,
вырождает JOIN в CROSS JOIN). Работает с любыми типами JOIN, далее
показан пример с обычным:

```sql
SELECT x.col1, y.col2, ...
    FROM tablex x
    NATURAL JOIN tabley y;
```
________________________________________________________________________

Создание виртуальных таблиц:

```sql
( VALUES
    (a1, b1, ...), (a2, b2, ...),
    ...
    (an, bn, ...)
) AS alias (a, b, ...)
```

Создастся таблица с именем alias и столбцами a, b, ..., но в виртуальном
пространстве, без записи в БД.

При использовании в JOIN стоит использовать RIGHT OUTER JOIN, т.к. такие
данные ни с чем не связаны и могут не иметь соответствия в базовой
таблице.
________________________________________________________________________

### UNION, INTERSECT, EXCEPT ###

Объединение таблиц - `UNION`.

Следующий запрос производит выборку с объединением таблиц. Причем colx1
будет соответствовать coly1, и т.д. Выведется результат общий,
объединенный. Названия останутся от tablex (colx1, colx2, ...).

> **ВАЖНО!** При этом остаются только уник. записи, поэтому одинаковые
строки как бы объединятся в одну. Для предотвращения этого эффекта
следует использовать `UNION ALL`.

```sql
SELECT colx1, colx2, ... FROM tablex
    UNION SELECT coly1, coly2, ... FROM tabley;
```

Рассмотрим пример с интересной фичей:

Следующий запрос выдаст таблицу с полями col1 и tbl, при этом в первом
поле будут значения из обеих таблиц из полей col1 и col11, а во втором
будут в соответствие выставлены значения 'table 1' и 'table 2', заданные
явно. Т.о., во-первых, неуник. значения из разных таблиц не объединятся
в одно, т.к. теперь они будут представлять собой уник. записи; а
во-вторых, появится поле, которого не было ни в одной из таблиц, с явно
заданными значениями с объявлением, из какой таблицы какая строка
пришла.

```sql
SELECT col1, 'table 1' as tbl FROM table1
    UNION SELECT col11, 'table 2' FROM table2;
```
________________________________________________________________________

`INTERSECT` - пересечение мн-в.

По аналогии с UNION, только в данном случае выводит записи,
принадлежащие одновременно двум таблицам или выборкам.

> **ВАЖНО!** Не выводит дубликаты, для исправления - `INTERSECT ALL`.
________________________________________________________________________

`EXCEPT` - разница выборок.

По аналогии с UNION, только в данном случае выводит записи,
принадлежащие первой таблице и не принадлежащие при этом второй.
________________________________________________________________________

### РАБОТА С ДАТОЙ И ВРЕМЕНЕМ ###

Типы данных даты-времени поддерживает операторы:

- `+`, `-` м/ датами-временами и с числами.
- `*`, `/` с числами.
________________________________________________________________________

Текущие дата-время (точнее, в контексте SQL - дата-время начала данной
транзакции):

```sql
CURRENT_DATE
CURRENT_TIME
CURRENT_TIMESTAMP
CURRENT_TIME(точность)
CURRENT_TIMESTAMP(точность)
LOCALTIME
LOCALTIMESTAMP
LOCALTIME(точность)
LOCALTIMESTAMP(точность)
```

Кроме того, есть в PostgreSQL есть и другие ф-ции для текущей
даты-времени, необязательно привязанные к времени начала транзакции:

```sql
transaction_timestamp()
statement_timestamp()
clock_timestamp()
timeofday()
now()
```

Получение результатов всех вышеописанных ф-ций через SELECT-запрос:
`SELECT <current_smth>;`.
________________________________________________________________________

`EXTRACT(<field> FROM <dt>)` - извлечь поле (год, час и т.п.) из dt типа
данных дата-время.

Возможные поля:

- `century` - век.
- `day` - день месяца или дни в интервале.
- `decade` - декада (десятилетие).
- `dow` - день недели от 0 (вс) до 6 (сб).
- `doy` - день года от 1 до 365/366.
- `epoch` - число секунд с 1970-01-01 00:00:00 UTC или общее число
    секунд в интервале.
- `hour` - час от 0 до 23.
- `isodow` - день недели от 1 (пн) до 7 (вс).
- `isoyear` - год по недельному календарю ISO 8601 (неприменимо к
    интервалам).
- `julian` - юлианская дата (для интервала не определена).
- `microseconds` - микросекунды. На самом деле - значение секунд с
    дробной частью, умноженное на 1 000 000; включает и целые секунды.
- `millennium` - тысячелетие.
- `milliseconds` - миллисекунды. На самом деле - значение секунд с
    дробной частью, умноженное на 1 000; включает и целые секунды.
- `minute` - минуты от 0 до 59.
- `month` - для значений timestamp это номер месяца в году от 1 до 12, а
    для interval - остаток от деления числа месяцев на 12 от 0 до 11.
- `quarter` - квартал года от 1 до 4.
- `second` - секунды, включая дробную часть от 0 до 59.
- `timezone` - смещение часового пояса от UTC, представленное в
    секундах. Положительные значения соответствуют часовым поясам к
    востоку от UTC, а отрицательные - к западу.
- `timezone_hour` - поле часов в смещении часового пояса.
- `timezone_minute` - поле минут в смещении часового пояса.
- `week` - номер недели в году по недельному календарю ISO 8601. По
    определению, недели ISO 8601 начинаются с понедельника, а первая
    неделя года включает 4 января этого года.
- `year` - поле года. Стоит учесть, что года 0 не было, и это следует
    иметь в виду, вычитая из годов нашей эры годы до нашей эры.

Аналог ф-ции EXTRACT - `date_part('<field>', <dt>)`. Поле даты-времени
тут передается как строка.
________________________________________________________________________

Ф-ции задержки выполнения:

```sql
pg_sleep(сек)
pg_sleep_for(interval)
pg_sleep_until(timestamp with time zone)
```

Выполняются через SELECT-запрос.
________________________________________________________________________

Прочие ф-ции:

- `date_trunc('<field>', <dt>)` - отсекает компоненты даты до заданной
    точности.
- `isfinite(<dt>)` - проверка отличия даты от +/- бесконечности.
- `justify_days(<interval>)`, `justify_hours(<interval>)`,
    `justify_interval(interval)` - приведение дней, часов и дней +
    часов. В результате, например, первого интервал 25 часов сводится в
    1 день 1 час.
- `make_date(<year: int>, <month: int>, <day: int>)` - сделать дату по
    отдельным значениям полей. Также есть: `make_interval`, `make_time`,
    `make_timestamp`, `make_timestamptz`.
- `to_timestamp(<seconds: double precision>)` - преобразует время эпохи
    Unix (число секунд с 1970-01-01 00:00:00+00) в стандартное время.
________________________________________________________________________

В дополнение к этим функциям поддерживается SQL-оператор OVERLAPS:

```sql
(начало1, конец1) OVERLAPS (начало2, конец2)
(начало1, длительность1) OVERLAPS (начало2, длительность2)
```

Его результатом будет true, когда два периода времени пересекаются, и
false в противном случае.

### МОДИФИКАЦИЯ ОБЪЕКТОВ (ALTER) ###

Команда `ALTER TABLE` используется для модфикации таблиц. Внутри может
использоваться `ALTER COLUMN` для модификации поля внутри таблицы.

Синтаксис:

```sql
ALTER TABLE table
    <alter_command_1>,
    ...
    <alter_command_n>;
```

Базовые alter-запросы для полей:

- `ALTER TABLE table ADD COLUMN col ограничители` - `ADD COLUMN`
    позволяет добавить поле.
- `DROP COLUMN` - удалить поле.
- `ADD CHECK`, `ADD CONSTRAINT` - задать новые ограничители. Есть их
    соответствующие DROP-запросы. Есть альтернативный способ:
    `ALTER TABLE table ALTER COLUMN col SET NOT NULL;`
- `ADD PRIMARY KEY`, `ADD FOREIGN KEY` - добавление первичного или
    внешнего ключа.
- `... RENAME SMTH old_name TO new_name;` - переименовать что-либо.

Кроме того, можно сменить тип данных поля:

```sql
ALTER TABLE table
    ALTER COLUMN col SET DATA TYPE data-type;
```

Тут же может помочь `USING` и конструкция `CASE-WHEN-THEN-ELSE-END`:

```sql
ALTER TABLE table
    ALTER COLUMN col SET DATA TYPE data-type;
    USING ( CASE WHEN col = value_old1 THEN value_new1
                WHEN col = value_old2 THEN value_new2
                ...
                ELSE value_new_else
            END );
```
________________________________________________________________________

### ВЛОЖЕННЫЙ ЗАПРОС ###

Допустим, надо выполнить следующую команду:

```sql
SELECT ... FROM ...
    JOIN ... ON ...
    WHERE smth > num
```

При этом num определяется из другой или этой же таблицы. Тогда вместо
двух отдельных запросов можно сделать один:

```sql
SELECT ... FROM ...
JOIN ... ON ...
WHERE smth > (SELECT ... FROM ... ...)
```

Если вложенный запрос вернет больше одного значения, то выбирается для
сравнения первое. Если вложенный запрос вернет NULL, то и результат
всего запроса будет NULL.

Возможны применения не только для SELECT.
________________________________________________________________________

Можно обернуть в `WITH name AS (SELECT ...)`. Тогда вложенный запрос
можно использовать далее под элиасом name. Пример:

```sql
WITH ts AS
    (   SELECT ...
        ...
    )
SELECT ... FROM ... WHERE ts.col = n
```
________________________________________________________________________

### ПРЕДСТАВЛЕНИЯ ###

Служит для создания наименования для какого-то часто используемого
запроса SELECT. Далее можем обращаться к нему как к обычной таблице.
По сути представляет сохраненный запрос к БД.

Упрощенный синтаксис:

```sql
CREATE VIEW имя-представления [ ( имя-столбца [, ...] ) ]
    AS запрос;
```

Есть модификация `CREATE ... OR REPLACE` для обновления представления,
но имена полей должны оставаться неизменными.

`DROP VIEW [IF EXISTS] name;` - удаление представления.
________________________________________________________________________

Создать материализованное представление:

```sql
CREATE MATERIALIZED VIEW [ IF NOT EXISTS ] имя-мат-представления
[ ( имя-столбца [, ...] ) ]
AS запрос
[ WITH [ NO ] DATA ];
```

В момент выполнения команды создания материализованного представления
оно заполняется данными, но только если в команде не было фразы
`WITH NO DATA`. Если же она была включена в команду, тогда в момент
своего создания представление остается пустым, а для заполнения его
данными нужно использовать команду `REFRESH MATERIALIZED VIEW name;`.

`REFRESH MATERIALIZED VIEW name;` - обновление данных.

`DROP MATERIALIZED VIEW name;` - удаление материализованного
представления.
________________________________________________________________________

### ИНДЕКСЫ ###

*Индекс* - спец. структура данных, которая связана с таблицей и
создается на основе данных, содержащихся в ней.

Индексы позволяют повысить производительность БД. Данное улучшение
происходит за счет того, что по умолчанию записи в таблице хранятся в
неупорядоченном виде. В случае с PostgreSQL они хранятся в порядке
последнего добавления/изменения. Но чаще всего при SELECT-запросе нужны
записи с определенными значениями какого-то поля или в определенном
порядке.

Индексы помогают именно здесь - представляя собой ссылочную структуру
данных, индекс хранит и поддерживает легкий доступ к данным по порядку.
Т.о. на порядок-другой ускоряется подходящий SELECT-запрос. Но при этом
важно понимать, что и на создание индекса уходит много времени, и на его
поддержание приходится тратить ресурсы при каждом обновлении таблицы.
________________________________________________________________________

Команда создания индекса:

```sql
CREATE INDEX имя-индекса
    ON имя-таблицы ( имя-столбца, ...);
```

Кроме того, индекс автоматически создается при накладывании ограничителя
UNIQUE или PRIMARY KEY на поле.

По умолчанию порядок - возрастающий, а значения Null - в конце. Это
можно настроить через `ASC` (возрастающий порядок), `DESC` (убывающий
порядок), `NULLS FIRST` (эти значения идут первыми) и `NULLS LAST` (эти
значения идут последними). Например:

```sql
CREATE INDEX имя-индекса
    ON имя-таблицы ( имя-столбца NULLS FIRST, ... );

CREATE INDEX имя-индекса
    ON имя-таблицы ( имя-столбца DESC NULLS LAST, ... );
```

Создание индексов для поддержания уникальности:

```sql
CREATE UNIQUE INDEX имя-индекса
    ON имя-таблицы ( имя-столбца, ...);
```

Создание частичного индекса (предиката индекса) - т.е. индекса не по
всем значениям поля, а только удовлетворяющих условию:

```sql
CREATE UNIQUE INDEX имя-индекса
    ON имя-таблицы ( имя-столбца, ...)
    WHERE условие;
```
________________________________________________________________________

Удаление индекса:

```sql
DROP INDEX имя-индекса;
```

### ТРАНЗАКЦИИ ###

*Транзакция* - это совокупность операций над БД, которые вместе образуют
логически целостную процедуру, и могут быть либо выполнены все вместе,
либо не будет выполнена ни одна из них. В простейшем случае транзакция
состоит из одной операции.
________________________________________________________________________

Согласно теории БД транзакции должны обладать следующими св-вами
(известными как принципы ACID):

1. *Атомарность* (atomicity) - это св-во означает, что либо транзакция
    будет зафиксирована в БД полностью, т. е. будут зафиксированы
    результаты выполнения всех ее операций, либо не будет зафиксирована
    ни одна операция транзакции.

2. *Согласованность* (consistency) - это св-во предписывает, чтобы в
    результате успешного выполнения транзакции БД была переведена из
    одного согласованного состояния в другое согласованное состояние.

3. *Изолированность* (isolation) - во время выполнения транзакции другие
    транзакции должны оказывать по возм-ти мин. влияние на нее.

4. *Долговечность* (durability) - после успешной фиксации транзакции
    пользователь должен быть уверен, что данные надежно сохранены в БД и
    впоследствии могут быть извлечены из нее, независимо от последующих
    возможных сбоев в работе системы.
________________________________________________________________________

При параллельном выполнении транзакций возможны следующие феномены:

1. Потерянное обновление - когда разные транзакции одновременно изменяют
    одни и те же данные, то после фиксации изменений может оказаться,
    что одна транзакция перезаписала данные, обновленные и
    зафиксированные другой транзакцией.

2. Грязное чтение - транзакция читает данные, измененные параллельной
    транзакцией, которая еще не завершилась. Если эта параллельная
    транзакция в итоге будет отменена, тогда окажется, что первая
    транзакция прочитала данные, которых нет в системе.

3. Неповторяющееся чтение - при повторном чтении тех же самых данных в
    рамках одной транзакции оказывается, что другая транзакция успела
    изменить и зафиксировать эти данные. В результате тот же самый
    запрос выдает другой результат.

4. Фантомное чтение - транзакция повторно выбирает мн-во строк в
    соответствии с одним и тем же критерием. В интервале времени м/
    выполнением этих выборок другая транзакция добавляет новые строки и
    успешно фиксирует изменения. В результате при выполнении повторной
    выборки в первой транзакции может быть получено другое мн-во строк.

5. Аномалия сериализации - результат успешной фиксации группы
    транзакций, выполняющихся параллельно, не совпадает с результатом ни
    одного из возможных вариантов упорядочения этих транзакций, если бы
    они выполнялись последовательно.
________________________________________________________________________

Для конкретизации степени независимости параллельных транзакций вводится
понятие *уровня изоляции* транзакций. Каждый уровень хар-ся перечнем тех
феноменов, которые на данном уровне не допускаются.

Всего в стандарте SQL предусмотрено четыре уровня. Каждый более высокий
уровень включает в себя все возм-ти предыдущего:

1. *Read Uncommitted* - то самый низкий уровень изоляции. Согласно
    стандарту SQL на этом уровне допускается чтение грязных
    (незафиксированных) данных. Однако в PostgreSQL требования,
    предъявляемые к этому уровню, более строгие, чем в стандарте: чтение
    грязных данных на этом уровне не допускается.

2. *Read Committed* - не допускается чтение грязных (незафиксированных)
    данных. Т.о., в PostgreSQL уровень Read Uncommitted совпадает с
    уровнем Read Committed. Транзакция может видеть только те
    незафиксированные изменения данных, которые произведены в ходе
    выполнения ее самой.

3. *Repeatable Read* - не допускается чтение грязных (незафиксированных)
    данных и неповторяющееся чтение. В PostgreSQL на этом уровне не
    допускается также фантомное чтение. Т.о., реализация этого уровня
    является более строгой, чем того требует стандарт SQL. Это не
    противоречит стандарту.

4. *Serializable* - не допускается ни один из феноменов, перечисленных
    выше, в том числе и аномалии сериализации.
________________________________________________________________________

Синтаксис транзации:

```sql
BEGIN TRANSACTION ISOLATION LEVEL lvl;
smth
END; / COMMIT; / ROLLBACK;
```

`END` - автоматическое определение, что делать: COMMIT или ROLLBACK.
`COMMIT` - сохранить изменения, `ROLLBACK` - откат.
